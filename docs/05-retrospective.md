# 05 复盘与下一步

## 最难的问题

难点是成本与状态必须随失败和重规划累积。预算 10 的案例中，高配素材估价 12，改选轻量素材后为 8；已经发生的检索、脚本、估算时间不可凭空回退。标准脚本超时后，必须保留成功检索、将失败明确记录，并让模型选择精简脚本。保存草稿前还需重算预算与时间，避免依据过期估算写入不可行方案。

## 学习与改进

真正的模型闭环需要工具观察进入下一次模型请求。实现中使用一轮一个 function call，并把返回作为 tool message；真实记录表明模型能够根据成本超限和工具超时改变后续动作。模型也曾返回并行动作，因此增加了拒绝整批的控制，保证依赖顺序并让模型重新选择。

状态恢复比简单重试更有价值：已成功的检索不重做，失败脚本仍保留失败状态，保存失败不伪装成完成。重复请求在 SQLite 中按请求键只生成一份草稿。
